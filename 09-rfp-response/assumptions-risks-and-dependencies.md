# Assumptions, Risks, and Dependencies

## Assumptions this proposal depends on

| # | Assumption | If wrong, what changes |
|---|---|---|
| A1 | Al Noor decides build, not buy, before Phase 1 starts | This entire proposal's scope, team, and estimate would need to be reworked for a configuration/integration engagement instead |
| A2 | Executive sign-off on Finance's ownership role for KPI definitions is obtained during or before Phase 0 | Governance work (and everything downstream) stalls without a clear, approved owner to make definition decisions |
| A3 | Finance, IT, and at least one Property GM are available for the sessions each phase requires, on roughly the timeline proposed | Phase 0 and Phase 1 durations are the most exposed to this — see Timeline |
| A4 | Al Noor provides existing content (current KPI calculation logic, Excel consolidation workbook, any existing documentation of the escalation process today) rather than us reconstructing it from scratch | Reconstructing undocumented process knowledge from interviews alone would extend Phase 0 |
| A5 | Occupancy remains the only KPI with a confirmed definitional issue through this engagement's scope | If revenue/ADR/RevPAR turn out to need urgent attention, that's new scope, priced separately, not absorbed into this estimate |
| A6 | The fifth property's system and the regulatory reporting inventory are **not** required to be resolved before this engagement starts | Both are already scoped as separate future additions; if Al Noor needs them folded into this phase instead, scope and estimate both change |

## Risks

| # | Risk | Mitigation |
|---|---|---|
| R1 | Building the workspace before the KPI dictionary is actually agreed encodes today's ambiguity rather than fixing it | Phase 0 gates Phase 1 — no UX work starts until the occupancy definition and governance process are validated |
| R2 | Property GMs experience this as corporate-imposed standardization | Mandatory consultation and the variance register are core scope from day one, not a later addition |
| R3 | The current manual process gets disrupted before the new one is proven | Pilot (Phase 5) runs in parallel with the existing process for a full monthly cycle before full rollout |
| R4 | Stakeholder availability (Finance, IT, Property GMs) slips the schedule, particularly in Phase 0 | Flagged explicitly in Timeline as the single biggest schedule risk; we'd ask for named points of contact at kickoff, not ad hoc availability |
| R5 | Build-vs-buy is decided after Phase 1 has already started | We've asked for this decision as a Phase 0 exit criterion specifically to avoid rework mid-engagement |
| R6 | Localization/RTL and accessibility needs turn out to be larger than a design-pass can absorb (e.g., full Arabic content translation, not just layout) | Flagged in Team as a currently-unscoped item; would need confirming and, if substantial, pricing separately |

## Dependencies (owned by Al Noor, not the proposing team)

| Dependency | Status per the RFP | Blocks |
|---|---|---|
| Build-vs-buy decision | Open | Phase 1 start; this entire estimate's validity |
| Executive approval of Finance as KPI/definition owner | Pending | Phase 0 completion; any governance decision made during the engagement |
| Fifth property's PMS and reporting flow | In progress | Including the fifth property in this engagement (currently out of scope, see Scope of Work) |
| Government/tourism-authority reporting inventory | Not yet started | Regulatory reporting integration (currently out of scope, see Scope of Work) |

None of these are things we can resolve on Al Noor's behalf — they're flagged here so both sides go into a signed SOW with the same list of open items, rather than discovering them mid-engagement.
